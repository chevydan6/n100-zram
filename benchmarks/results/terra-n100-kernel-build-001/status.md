# N100-focused experimental kernel build

At the user's direction the broad Fedora module build was stopped and retained. A separate copy-on-write output tree reuses its intermediate files without changing that checkpoint. The new configuration began with the same experimental GHY kernel configuration and used `localmodconfig` with the laptop's captured loaded-module list, followed by explicitly restoring common external-device and virtual-machine drivers from the Fedora configuration. The module setting count dropped from 4,845 to approximately 330. The user requested higher priority, so the build runs with four workers at normal priority under the exclusive native lock.

The recorded configuration retains Intel graphics, the present MMC controller and Btrfs root, scalar and SIMD GHY support, stock LZ4/zstd/lzo-rle, USB storage/UAS, common USB and wired Ethernet adapters, NVMe/AHCI, common FAT/exFAT/NTFS/ext4/Btrfs filesystems, and virtio for isolated testing. The Realtek USB Ethernet symbol is `USB_RTL8152`; the initially requested generic name `R8152` was absent and corrected before the final configuration. The loaded-module and requested-driver lists and final configuration are retained. Localmodconfig cannot predict hardware that was not connected or modules not loaded at capture time; this is a selected common subset, not a promise of every peripheral.

The build completed successfully as `7.2.11-n100-gzram`, producing a 16,667,136-byte kernel image and 335 `.ko` modules. The ZRAM module advertises `ghy-bitdirect`, `ghy-simd`, and `lz4-ghy`; image, config, module, and symbol hashes are recorded in `completed-build.json`. This is a build result, not a claim that the kernel boots or works on the laptop. It requires an isolated boot test, ZRAM correctness, hardware support validation, and a recovery plan before any physical boot. It has not been installed and normal GRUB, kernel and ZRAM settings remain unchanged.

At the user's request, the stopped broad build's `out` directory and duplicate local logs were deleted after verifying that the active build used `out-n100` and that the historical logs had been preserved here and in the earlier checkpoint. The isolated source and toolchain are shared with the active build and were retained. Btrfs copy-on-write sharing means deleting the old directory does not necessarily free its apparent 3 GiB size immediately.
