# Experimental GZRAM kernel build checkpoint

The user requested an experimental kernel. A separate Linux 7.2.11 tree was extracted from the previously [signature-verified Fedora source RPM](../terra-source-signature-001/findings.md), and the Fedora source patch and its separately packaged `Makefile.rhelver` were applied. The existing experimental scalar and SIMD GHY ZRAM backends were copied into the isolated tree. `checkpoint.json` records source and configuration hashes and confirms 56 copied driver files match their source files. The source tree is not a claim of an exact reproducible Fedora binary; the experimental kernel config is derived from the installed config with a distinct local version, GHY enabled, module auto-signing disabled, and debug information/BTF disabled to reduce build cost. The existing installed kernel, boot entries and stock ZRAM were not modified.

The full `bzImage modules` build is running in `build/terra-custom-kernel-001/` using two low-priority workers under the existing exclusive lock. The first short build was stopped to acquire that lock, then the locked build failed because Fedora's separately packaged `Makefile.rhelver` was missing. Both logs are preserved, as is the failed attempt to use unavailable `patch`; the Fedora patch was checked and applied using the method used by the RPM spec. The signed RPM's makefile was extracted and the locked build was restarted. The kernel is **not yet complete, installed, booted or validated**.

Once complete it still requires module staging, an isolated boot and GZRAM correctness gates, and a safe physical boot/recovery plan. The kernel is unsigned and Secure Boot compatibility is unverified. No routine ZRAM change is authorized by the build alone. Build result and any errors must be recorded in a later checkpoint; this file is not proof that the still-running command succeeded.
