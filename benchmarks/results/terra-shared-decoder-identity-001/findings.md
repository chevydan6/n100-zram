# Shared decoder and identical-input check

The combined sampling timing harness encodes each candidate separately but calls the same parent scalar decoder for scalar streams and the same parent AVX2 decoder for AVX2 streams. This analysis regenerated each of the 128 frames per measured corpus using the exact hash-verified benchmark libraries, checked corpus hashes against the recorded timing checkpoint, and compared frame bytes with the corresponding parent frame. It does not store source pages or compressed frames. The matched timing run was not repeated or changed.

Of 84 corpus/candidate/ISA combinations, 78 had byte-identical frames for all 128 pages. Among these fully identical inputs, the largest absolute median paired decoding-time difference was 2.06% (64-word scalar candidate on mixed pages, session medians -2.16%, -0.21% and -2.06%). Another case showed a +1.84% median (64-word AVX2 on the dense-hit fixture), with session medians +7.62%, +0.73% and +1.84%. All counts, absolute time medians and session changes are in `result.json`.

The decoder function and bytes are identical for these cases, so such differences cannot establish an algorithmic decoder improvement. Memory-bank address/layout, task order, caches, preemption, frequency and timing noise can still differ; this check does not isolate which caused any observed gap. For the six combinations with changed frames, the same decoder sees different inputs and a decoding-time change cannot be attributed to encoder code or layout alone. The check is userspace-only and says nothing about ZRAM, kernel FPU boundaries or system responsiveness.
