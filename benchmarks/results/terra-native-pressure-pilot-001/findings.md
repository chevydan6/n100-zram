# Physical cgroup pressure pilot

On the physical N100 running `7.2.11-n100-gzram-btf`, two randomized rounds compared zstd, LZ4, lzo-rle and GHY bitdirect using a separate temporary 192 MiB high-priority ZRAM swap device. Existing zram0 and the hibernation swap remained active throughout; temporary priority can route other system swap activity into the test device, so its statistics are not necessarily exclusive to the workload. Each trial ran a dedicated systemd cgroup with `MemoryHigh=128M`, `MemoryMax=256M`, `MemorySwapMax=160M`, and a 192 MiB synthetic working set based on eight retained corpora. It checked sampled content and launched four GCC syntax checks. Cgroup telemetry, faults, timings, package energy and device allocator statistics were sampled. The temporary swap was deactivated and device reset between trials, then removed; original swap configuration and zstd selection matched afterward. The workload passed all checks.

Peak sampled cgroup swap use ranged from 77,795,328 to 87,109,632 bytes (74.2–83.1 MiB), demonstrating real swap activity. The workload itself finished in approximately 0.56–0.95 seconds; the enclosing monitoring loop and service overhead produced 1.0–1.5 seconds and package totals of 3.5–6.0 J. The device was almost empty when the process exited, so its final `mm_stat` is not peak allocation; sampled peak allocated sizes and the raw time series are retained. Two trials per algorithm, subsecond execution, 0.5-second sampling, externally affected package energy, a repeated synthetic working set, and no real browser or foreground responsiveness measurement make this a harness feasibility pilot, not a reliable compressor ranking or 10% real-world result. No kernel cycles or battery-life metrics were measured. The user was physically present and accepted manual reset if needed; automatic hard-hang recovery remains unverified.

The retained source and full raw results document the configuration and randomized order. Follow-up needs a longer representative application workload, more matched repetitions, phase-specific latency and sustained energy, sampling peaks with suitable resolution, and verification that other system swap activity does not confound the comparison.
