# Guest CPU-hotplug and ZRAM I/O overlap

The earlier coexistence test offlined and onlined CPU1 only after the ZRAM I/O client had finished. This diagnostic tests the missing overlap using the same hash-verified experimental module in a diskless, networkless AVX2-exposed KVM guest running Fedora kernel 7.2.11. It does not load a module on the host or modify its active ZRAM.

A guest-only copy of the existing round-trip client starts four independent I/O workers and a fifth thread that offlines and onlines CPU1 ten times. The hotplug thread waits for at least 16 completed write/read checks, records the counter, performs its ten cycles, then records it again. The client rejects a failed hotplug operation or no progress between the counter snapshots. The protocol confirms progress during the overall hotplug sequence; it does not prove that a read or write was in a critical section at the exact instant of every CPU transition. It does not stress concurrent writes to the stock ZRAM device or prove all CPU-hotplug interleavings.

Two module-load cycles tested `ghy-bitdirect`, `ghy-simd`, private `lz4-ghy`, stock LZ4 and zstd against 26 retained synthetic corpora. All ten expected hotplug-window markers had increasing I/O counts and reported ten successful cycles. All clients passed read/write/discard verification; subsequent CPU1-pinned verification, stock-device data checks and module unload checks passed. The original guest runner's status passed, host settings hashes matched before and after, and no experimental host module was loaded. The client also refused direct invocation on the host with exit code 3. The additional shared atomic counter and hotplug thread are correctness instrumentation; no timing or energy inference is valid.

`client.c`, `guest-runner.py`, full guest log, result JSON, binary hashes, and `analyze.py` are retained. The launcher copy expects its existing unchanged parser modules beside it; the recorded runner was staged in `build/` with those files. `analyze.py` validates ownership and coverage of the hotplug markers in a directory containing `result.json` and decompressed `serial.log`. Only one AVX2-exposed guest was run; forced AVX2-hidden fallback and other CPU counts were not tested by this overlap experiment. This does not establish native recovery, stability or performance, and native experimental testing remains gated.

The marker analyzer additionally rejected test logs with a missing marker, a duplicate marker, or an altered cycle count. These are protocol checks, not proof of every possible concurrency interleaving.
