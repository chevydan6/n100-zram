# Zstd match-finder prefetch candidate

An opt-in x86-64 candidate adds a prefetch of the next long-hash-table entry in the no-dictionary double-fast match finder. It does not deliberately change the search or frame format. Fresh userspace zstd 1.5.7 control and candidate builds used matching GCC `-O3 -fPIC -march=x86-64-v3 -fno-tree-vectorize` settings apart from the candidate macro. On the N100, nine randomized same-round observations covered 26 corpora. The candidate and control produced identical frames on all 3,328 checked pages, and candidate frames decoded with the candidate, control and independently loaded system library; truncation, undersized output and canaries were checked. This finite validation is not complete-codec sanitizer, exhaustive malformed-frame or kernel stability testing.

The [table](tables.md) retains all times. Paired median compression time was -1.5% on bash executable, +1.5% on git executable, +6.8% on libc executable, -2.5% on mixed and +4.4% on clusters50. Python/ctypes overhead, dynamic frequency, compiler code layout and short runs limit interpretation. The mixed results and material regressions do not support kernel integration or routine use. No energy, actual ZRAM behavior or application performance is established.
