# First physical BTF kernel boot

On October 30, 2026, after the user confirmed physical presence, the previously verified one-time entry booted `7.2.11-n100-gzram-btf` on the Lenovo N100. The saved Fedora default had been verified before selecting the entry; postboot GRUB metadata still requires a privileged check. `/boot/efi` is mounted as VFAT, SELinux is enforcing, `/sys/kernel/btf/vmlinux` is nonempty, and both the hibernation swap file and `/dev/zram0` are active. The stock `[zstd]` algorithm remains selected; experimental algorithms are registered but not selected for swap. There were no failed system units at initial inspection. Wi-Fi reports connected and audio modules are loaded, but physical audio and other hardware functionality still need user confirmation.

The boot journal reports `bpf-restrict-fs: LSM BPF program attached`, unlike the failure from the previous experimental boot. This verifies attachment messages, not full security equivalence. No AVC denial appeared in the selected journal query. Desktop portal dependency failures occurred, but the preceding stock Fedora boot also logged the same class of failures; causation and application impact remain unverified. Selected journal lines are preserved. The first boot's SELinux labeling failure did not recur in these initial checks.

This is an initial boot observation only: there has been no native GZRAM codec test, pressure, speed, memory, responsiveness, energy or stability measurement. `panic`, `panic_on_oops`, and `nmi_watchdog` were zero, pstore backend was `(null)`, and no `/dev/watchdog` was visible. No independent hard-hang recovery has been proven. The previous emergency-mode power cycle returned to the saved Fedora entry but cannot prove all failure modes. Native compression tests require a fresh recovery and lock assessment; the normal boot and stock swap settings are not to be changed by this observation.
