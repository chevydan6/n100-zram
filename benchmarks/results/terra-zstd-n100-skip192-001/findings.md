# Milder page-only zstd match-search skip candidate

This is the same opt-in x86-64 page-only double-fast skip experiment as the [128-byte candidate](../terra-zstd-n100-skip-001/findings.md), using an increment of 192 instead of the stock 256. Fresh matched control and candidate userspace Zstandard 1.5.7 libraries were tested in nine randomized same-round comparisons on 26 corpora. Of 3,328 pages, 2,981 produced byte-identical frames; candidate and control frames were independently decoded, and truncated/undersized cases checked. The full candidate ASan/UBSan check passed 3,328 pages across four threads with round trips, truncated input, canaries and mutated frames. Patch, full results, build and sanitizer logs are retained.

The [table](tables.md) retains all timing and size outcomes. Paired median compression time was -3.3% for random and -16.3% for sample16-dense-hit, but +0.5% for bash executable, +2.7% for libc executable and -0.6% for mixed pages. The word-tail64 corpus grew from 272,896 to 281,088 bytes (+3.0%), while halfzero grew 0.096%. This reduces but does not remove the 128-byte candidate's size regression, while also reducing its random-page speedup. Timing noise, userspace/ctypes overhead and synthetic workloads prevent an overall claim. No package energy, native ZRAM performance, allocator-rounded memory or application-pressure result is established. This candidate is not promoted to a kernel or normal configuration based on these results.
