# Scalar LZ4 coexistence module and correctness

The strongest previously measured scalar candidate uses `LZ4_MEMORY_USAGE=12` (4 KiB table), with a private `LZ4_MEMORY_USAGE=14` matched control. Prior userspace work measured faster compression but some larger executable outputs; see [the previous findings](../native-lz4-scalar-confirm-energy-002/findings.md). For the currently running BTF kernel, a separate namespaced experimental ZRAM module was built from the existing small-table sources and matched control, adapted using the earlier coexistence namespace pattern. Source copies, hashes, build output and module SHA-256 `b233b00e47d022a8c241af06603c54a9de2c38324022bb703d058929c99ceec8` are retained. The standard LZ4 and zstd backend source files match the current kernel source byte for byte; this still is a separate ZRAM driver, not the active stock driver.

Two diskless exact-kernel guest runs, with AVX2 hidden and exposed, passed stock-plus-namespaced coexistence, CPU-hotplug and unload checks. Each tested five algorithms in two passes, 26 corpora and 24,197 checks per algorithm/pass. A bounded physical correctness run then exercised small-table, matched control, standard LZ4, zstd and lzo-rle with 2,048 comparisons each on a separate 16 MiB device. All passed, the device was removed, the module was unloaded and existing swap settings matched before and after. Prior userspace validation and guest tests do not prove all malformed input or long-term native safety. The research module is not installed or loaded after testing; no boot configuration or active zstd swap was changed.
