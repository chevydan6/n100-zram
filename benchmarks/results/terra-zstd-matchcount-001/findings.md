# N100-oriented zstd match-count prototype

The kernel zstd compressor has a scalar match-length loop in `lib/zstd/compress/zstd_compress_internal.h`. This standalone C experiment compares a reimplementation of its 8-byte comparison and 4/2/1-byte tail behavior against two additive candidates: a 32-byte grouped loop and a version that checks the first 8-byte word before entering that loop. It uses scalar x86-64-v3 compilation with auto-vectorization disabled and targets the N100's 64-bit operations and BMI1 bit scan. The compiler's retained disassembly shows its actual generated ordering; no claim is made that the loads execute in parallel. It does not change zstd framing or any kernel code.

Fifteen same-round observations per tested match length were run on the physical N100 pinned to CPU 0, for both all-equal buffers ending at that length and mismatches at that position within a 512-byte buffer. The [tables](tables.md) contain absolute times and paired median changes. The grouped candidate helped several long matches but regressed some short cases; the first-word guard removed the observed 8-byte mismatch regression in this microbenchmark while retaining some long-match gains. This highly repetitive component benchmark does not measure the distribution of zstd matches, compression ratio, full-codec performance, kernel SIMD overhead, package energy or responsiveness. Function placement, branch prediction and compiler differences could materially change the outcome. The control is a behaviorally equivalent standalone reimplementation, not a byte-for-byte build of the original zstd function. No N100-wide or end-to-end improvement is established.

Each of three implementations passed one million randomized cases across four threads and guarded page-end checks for every length through 512 bytes; the final code also passed ASan/UBSan using locally extracted runtime libraries. This does not test complete zstd round trips, malformed frames, output buffers, or format compatibility. Raw timings, source, sanitizer output and disassembly are retained; earlier two-variant exploratory timings are not the final three-variant comparison. Next, integrate an opt-in guarded candidate into an isolated copy of the exact kernel zstd compressor, validate against an independent decoder and unchanged controls, and benchmark the whole codec before considering a kernel gate or native use.
