# Physical ZRAM zstd level screen

The running kernel's zstd backend accepts a per-device compression level via `algorithm_params`; its default is level 3. Five randomized rounds compared default, explicit levels 1, 2 and 3, and LZ4 across eight retained 512 KiB corpora on a temporary non-swap device. Each used 0.5-second repeated direct-I/O write and read batches, a warmup write and final readback verification. All 200 trials passed; the temporary device was removed and active stock zstd swap configuration was unchanged. Energy is CPU-package RAPL around each batch, including other activity. The JSON `scope` string saying no energy is stale from the inherited harness; named package-energy fields are actual readings.

The [tables](tables.md) include write/read time and energy normalized by completed operations, compressed bytes, allocated bytes and same-round timing changes. On bash executable pages, level 2 wrote in median 30.03 versus 38.50 µs/page for default (-22.8% paired time), with 585,728 sampled allocated bytes for both; compressed bytes rose from 336,038 to 337,623. Level 1 was faster but allocated 647,168 bytes. On mixed pages, level 2 wrote 14.05 versus 17.32 µs/page (-18.2%), but allocated 716,800 versus 667,648 bytes. On sparse words it wrote 17.52 versus 19.40 µs/page (-12.4%) but read 5.26 versus 4.94 µs/page (+5.8% paired) and allocated 454,656 versus 425,984 bytes. Incompressible pages also wrote faster at levels 1 and 2, but LZ4 remained faster. Explicit level 3 produced the same recorded compressed bytes as default on these sets; small timing differences are noise or runtime variability, not a claimed optimization.

This is a 4 KiB-page synthetic direct-device screen, not an N100-specific code change, actual swap pressure, full application responsiveness, battery life or proof of a safe default change. Five observations, short energy batches, dynamic frequency and allocator noise constrain inference. It identifies level 2 as a candidate for matched pressure testing, while retaining its size and read regressions. Raw per-trial records, order and corpus hashes are retained.
