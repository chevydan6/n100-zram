# BTF kernel physical-boot preparation

The BTF build and isolated device correctness results are in [the build record](../terra-n100-btf-build-001/status.md). No installation or reboot is performed by this preparation checkpoint. The normal Fedora kernel, stock zstd ZRAM and hibernation swap were active at inspection. Secure Boot was disabled and SELinux enforcing. The native-validation lock was not held, and no build or QEMU process was active at inspection; recheck immediately before executing anything.

The scripts adapt the prior separate-entry procedure to the BTF release, refuse to overwrite the target, and check the running and saved default kernel. They require root. `prepare-initramfs.sh` takes the existing project lock and generates a host-only image using the staged module tree. Independently inspect the generated initramfs with `lsinitrd` for the laptop's storage and boot filesystem drivers and the intended ZRAM module before installation. The installation script must itself be run under the same exclusive lock; it restores and verifies SELinux module labels, generates dependencies, creates a separate boot entry and verifies the original default. It does not schedule a boot. These scripts have only passed syntax checks; they have not yet been executed for this release. Root authorization may require the local graphical authentication agent.

Before a physical boot, verify file hashes, module labels after depmod, boot entry and saved default, EFI mount, normal swap, available memory, lock ownership, user presence and a recovery route. The previous one-time entry returned to the normal kernel after the emergency-mode incident, but hard-hang recovery is not verified. A physical boot must start with stock zstd, and check storage, graphics, input, networking, SELinux, systemd BPF restrictions and swap before any GZRAM experiment. Do not interpret the VM gate as physical stability or performance evidence.

## Installation checkpoint, October 30

The host-only initramfs was generated under the project lock. Dracut reported a `realpath` warning because the release was not yet installed; inspection found the staged `sdhci-pci`, `mmc_block`, FAT, VFAT and ZRAM modules in the image. SHA-256 of the 123 MiB initramfs is `28328846514fffaeb09e388a54600ed981dd53dba01c1102b517ab5d4bac4d6a`.

The separate BTF boot entry was installed under the lock. Installed kernel, initramfs and ZRAM module hashes matched the staged artifacts, and the saved default remained `/boot/vmlinuz-7.2.11-200.fc44.x86_64` with empty `next_entry`. A post-install dry run found that `depmod` had recreated index files with generic module labels after the installer's label check. `restorecon -RF` was applied to the experimental tree only, and a subsequent `restorecon -nRv` produced no changes; `modules.dep` then had `modules_dep_t`. The installer has been corrected to run label restoration and verification after `depmod`. This was an installation verification finding, not proof of a boot failure.

The BTF kernel is installed but has not been physically booted. No next boot has been selected, no reboot scheduled, and normal stock zstd swap remains active. Physical boot, systemd BPF restrictions, hardware, hang recovery, stability and actual GZRAM performance remain unverified.
