# First bounded physical ZRAM device correctness check

On the physical Lenovo N100 running `7.2.11-n100-gzram-btf`, after the user explicitly accepted manual power-button recovery in the event of a hang, the root helper took the established exclusive lock, hot-added a separate 16 MiB ZRAM device, and tested LZ4, zstd, lzo-rle, GHY bitdirect, GHY SIMD and LZ4-GHY. It wrote and independently reread 1,024 pages from eight existing 128-page corpora (bash and libc executables, sparse words, repeat8, period127, mixed, clustered and random). Four threads wrote disjoint pages with `O_DIRECT`; each algorithm completed 2,048 comparisons including a reverse-order reread. These comparisons cover this dataset and concurrent disjoint writes, not malformed frames or exhaustive concurrency.

All six algorithms passed, their I/O error counters were zero, and the test device was reset between algorithms and hot-removed in the `finally` cleanup. The snapshot of active swaps, zram0 size and its selected zstd compressor matched before and after. The helper did not replace or reset zram0 or activate swap on the test device. Raw JSON, input hashes and code are retained. This single fixed-order, small synthetic correctness run is not a speed, energy, pressure, representative-memory or production-readiness result; the recorded allocation values are not a controlled performance comparison. It does not establish that the SIMD path actually executed, or prove recovery from a hard hang. The automatic watchdog and crash-log limitations remain; manual reset risks unsaved data. The normal kernel remains the saved boot default.
