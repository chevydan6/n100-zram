# Exact-kernel guest ZRAM allocator observation

A diskless, networkless exact-kernel KVM guest ran the existing namespaced experimental ZRAM driver alongside the guest's stock ZRAM device. The round-trip client wrote and independently read 26 retained synthetic/executable corpora, rotated the final page generation, and discarded one page. Immediately after each algorithm's first client pass, the guest read its experimental device's `mm_stat`; this is the kernel's actual guest ZRAM allocation accounting, not an estimate from userspace frame lengths. The client subsequently repeated I/O on CPU1 after offline/online, checked stock-device data, reset the device, and verified unload. Two module-load cycles covered scalar GHY, the earlier guarded SIMD GHY prototype, private LZ4 control, standard LZ4, LZO-RLE and zstd. This is not the newer userspace sampling candidate.

All 12 algorithm/cycle records passed the existing device protocol and four-worker round-trip checks. Each observation contained 13,627,392 bytes of original page data and 256 same-filled pages. The guest had 256 MiB and two vCPUs; the 26 corpora are deliberately balanced test fixtures, not an observed workload or pressure trace. The current experimental `ghy-simd` prototype and its controls are guest modules; no experimental host module was loaded, and the host ZRAM/frequency setting hashes matched before and after. Exact inputs, module/kernel hashes, all nine `mm_stat` fields and raw serial output are retained in `guest-result.json` and `guest-serial.log.gz`.

For the first / second cycle, SIMD GHY reported compressed payload 6,208,498 / 6,208,498 bytes and allocator usage 7,479,296 / 7,516,160 bytes. Guest zstd reported 5,927,139 / 5,927,139 compressed bytes and 7,503,872 / 7,495,680 allocated bytes; standard LZ4 reported 6,480,549 / 6,480,549 compressed bytes and 7,741,440 / 7,733,248 allocated bytes. Thus GHY's compressed count was 4.75% above zstd in both cycles, while GHY's allocator total was -0.33% / +0.27% versus zstd and -3.39% / -2.81% versus LZ4. LZO-RLE, scalar GHY and private LZ4 values are preserved in the raw result. These are two sequential cycles, not independent randomized trials or statistically supported overall gains. The allocator can retain partially used class pages, so compressed bytes and allocated bytes need not move together.

The observation is meaningful for this exact synthetic mixed corpus and guest driver. It does not establish native ZRAM memory usage, real reclaim mix, memory pressure, CPU time, latency, package or laptop energy, or performance relative to the user's active stock zstd device. The once-discarded slot, page history, algorithm ordering and guest memory environment affect totals. The guest round-trip checks do not substitute for verified native hard-hang recovery. Experimental host testing remains gated.
