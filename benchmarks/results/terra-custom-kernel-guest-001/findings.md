# N100-focused GZRAM kernel: isolated boot and ZRAM checks

The newly built `7.2.11-n100-gzram` kernel was booted in two separate diskless, networkless KVM guests on the physical N100, each with two vCPUs and 256 MiB RAM. The built modules were staged under the repository's `build/` tree, not installed into the host. The launcher resolves dependencies from that staged module tree and loads them only in the guest. One guest exposed AVX2 and the other hid it.

Both guests completed two ZRAM module load/unload cycles, testing `ghy-bitdirect`, `ghy-simd`, the private `lz4-ghy` hybrid, stock LZ4, zstd, and lzo-rle. For each algorithm and cycle, the existing client used four workers and 26 retained 128-page corpora; it checked independent writes/reads, varied page contents, zero/same-word handling and discard. There were 12 successful client records and 290,364 reported checks per guest. The guest algorithm selection and reset protocol passed. The AVX2-hidden run checks the guarded dispatch configuration, but this uninstrumented run has no branch counters and does not prove how many SIMD calls occurred.

Host stock ZRAM algorithm, size, module identity and CPU policy hashes matched before and after both guests, and no experimental host module was detected. The VM tests are correctness gates, not measurements of native performance, energy, physical graphics/network/storage support, hard-hang recovery, production readiness or actual ZRAM memory pressure. They do not prove all malformed inputs or concurrency interleavings. Prior userspace and exact-Fedora-kernel tests provide additional coverage but are not a substitute for validation on this custom kernel.

Raw guest logs and JSON records, including kernel, module, input and dependency hashes, are retained here. The prior build record is [here](../terra-n100-kernel-build-001/status.md). The custom kernel has not been installed or booted on the physical laptop; normal GRUB, stock kernel and ZRAM configuration remain unchanged.
