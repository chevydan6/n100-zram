# Manual embedded-controller reset research

Chromium's [hang-debugging guide](https://www.chromium.org/chromium-os/developer-library/guides/debugging/debugging-hangs/) lists holding the power button for at least eight seconds and, as a last resort, Refresh+Power as possible recovery methods on Chrome devices. Its [keyboard-controlled reset design](https://www.chromium.org/chromium-os/chromiumos-design-docs/keyboard-controlled-reset-circuit/) describes a hardware circuit that can reset the embedded controller and system. The [Lenovo user-guide page](https://support.lenovo.com/us/en/manuals/sg10315-user_guide) identifies the 14e Chromebook Gen 3 documentation. These are candidate manual recovery paths, not proof that this particular machine with its current firmware and Fedora installation implements them as described.

A hardware reset or forced power-off can lose unsaved data and is not equivalent to a demonstrated automatic watchdog, panic recovery, persistent crash logs, alternate-kernel boot, or restoration of swap after a failure. A successful reset under normal operation would not alone prove recovery from every hard-hang failure mode. Any future physical check requires the user to be present, a prepared and saved recovery/restoration plan, and explicit safeguards appropriate to the check. No keys were pressed, device reset, kernel module loaded, or system setting changed as part of this research. The existing native experimental test gate is not satisfied by documentation alone.
