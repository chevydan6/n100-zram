# GZRAM measured status, 2026-10-28

The additive [Astra development checkpoint](GZRAM-ASTRA-20261028.md) now includes
completed local timing cohorts and two completed package-energy cohorts,
format-compatible scalar/SIMD experiments and isolated kernel correctness gates.
It confirms specific sparse scalar gains and retains regressions against LZ4.
It does not establish a production ZRAM improvement or replace SOL's historical
measurements below. The local machine currently uses stock zstd ZRAM; historical
lzo-rle comparisons retain their original system configuration and scope.

The independent word scanner and mixed decoder provide specific userspace
benefits, but the latest vector-tail change trades some scalar speed for AVX2
encoding speed. No combined policy is accepted as a general compressor or a
production ZRAM default. Kernel integration of these GZRAM policies is pending.

## Completed experiments

All cohorts use the physical Intel N100, twelve corpora, three sessions, nine
recorded shuffled rounds per session, and separate encode/decode measurements.
The earlier codec controls, encoded-size losses and all measured regressions
remain available.

The two latest continuous cohorts had fully scheduled PMU groups and package
energy available in every recorded batch. Their native services completed
successfully, their collectors finished, the benchmark lock was released and
temporary sleep inhibition ended. Raw private checkpoints, access credentials
and machine recovery records are excluded from this repository. Published CSVs,
sanitized metadata, relative telemetry and validation logs are retained.

## Confirmed benefits and remaining tradeoff

At 1024-byte internal blocks, the clean wordmixed repeat measured a 43.14%
reduction in scalar half-zero encoding time and a 13.11% reduction in AVX2
sparse-word decoding time relative to matching guard32 controls. AVX2 half-zero
encoding time increased 2.73%. These are session-paired median changes; encoded
size was unchanged for these comparisons.

The splittail candidate gives the vector classifier an independent byte tail,
retaining the integer word scanner and mixed decoder policy. Its new native
cohort preserved all preceding 44 variants, with identical corpus hashes; all
15 preceding codec `.text` sections matched the previous native build.

| Splittail, 1024-byte blocks | Time change |
|---|---:|
| AVX2 half-zero encoding versus wordmixed | -1.77% |
| AVX2 half-zero encoding versus guard32mixed | +0.02% |
| AVX2 half-zero encoding versus guard32 | -0.69% |
| Scalar half-zero encoding versus wordmixed | +10.30% |
| Scalar half-zero encoding versus guard32 | -37.18% |
| AVX2 sparse-word decoding versus guard32 | -12.90% |

Encoded size was unchanged in all listed comparisons. Thus the vector-tail
change removes the observed AVX2 encoding penalty against the existing mixed
control while giving back part of wordmixed's scalar gain. The scalar regression
must remain visible; splittail is a research control, not an overall replacement.
The data support further investigation of scalar code generation and layout;
they do not establish a causal explanation for that regression.

Normal, guard-boundary, byte-identical encoding, independent decoding,
malformed-frame and concurrency checks passed for both additions. ASan/UBSan
also passed. Correctness and code-generation inspection are separate from the
native performance evidence. Hosted workflows were previously disabled; no
hosted CI pass is claimed here.

## Reproduce the direct comparisons

Each result directory contains `paired.md` and `paired.json`, including losing
cases, all corpora and separate directions. The analysis accepts either the
private checkpoint format or the published sanitized metadata:

```sh
python3 gzram/tools/analyze-paired.py \
  --input benchmarks/results/native-gzram-splittail-001 \
  --output build/splittail-paired-review \
  --controls guard32 guard32mixed wordmixed
```

The output directory must be new. The default control is guard32 for the older
cohorts; the splittail report explicitly includes all three controls. Changes
are the median of three session median ratios, with nine paired rounds per
session. Listed session ranges are descriptive ranges, not confidence intervals.
The CSV rows and metadata permit other analyses without discarding any trials.

These are warm-cache userspace codec measurements. Kernel SIMD state-management
costs and end-to-end ZRAM behavior are excluded. Package energy covers each
whole batch, including bookkeeping and background activity; it is not laptop
energy. No application-responsiveness or production acceptance follows from
these results. Next work should preserve the faster scalar path alongside the
AVX2 fix, then establish whole-codec profitability before any GZRAM kernel trial.
